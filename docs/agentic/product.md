# Product Context

## 产品判断

这是一个个人、本地优先、每天打开 Obsidian 即可阅读的 AI 前沿资讯工作流。核心产品不是抓取器、模型编排器或安全平台，而是“持续产出值得占用注意力、证据可追溯、无需日常维护的资讯”。

## 用户与环境

- 单一用户、单台可信 Windows 电脑。
- Obsidian Vault：`D:/personal/ObsidianVault`。
- 公开引擎：`D:/Agent_programs/obsidian_workflow_open`。
- 私有上下文：`D:/personal/obsidian_workflow`。
- 运行时：`D:/personal/obsidian_workflow-runtime`。
- 不购买 OpenAI API；使用用户现有 Codex 套餐。
- 电脑休眠或关机时不运行，也不唤醒；恢复后补跑。

个性化只使用私有的 `UserContextContract-v7.3.json`，不得从 Vault 其他笔记推断用户身份、职业或兴趣。

## 核心用户任务

1. 早上打开 Obsidian，快速知道 AI 工程与前沿能力发生了什么实质变化。
2. 在 30 秒内判断今天是否值得深入读；有价值时用 5–8 分钟读完。
3. 每条重要判断能回到原始证据，知道不确定性和下一观察信号。
4. 系统失败时看到可信状态，而不是昨日内容、空日报或伪成功。
5. 平时无需运行命令、整理文件或照看进程。

## 产品范围

第一阶段只交付 AI Daily；稳定后依次交付 Weekly、IELTS Preview。三者共享同一采集、证据、状态和发布引擎，不复制工作流。

AI Daily 的优先级：

1. Agent、context engineering、harness、coding、evals 与工具链。
2. 模型、API、release、定价、推理与开源能力。
3. 影响工程决策的研究、安全和政策。
4. 高影响产业变化。

## 内容体验

- Top 最多 3 条，正文只保留真正重要的变化。
- 结构为：事件 → 机制 → 原始证据 → 对当前工作流的影响 → 不确定性 → 观察信号。
- 没有真实行动时写“无需行动”。
- 资讯不足时只发布状态 `NO_SIGNIFICANT_NEWS`，不生成空日报。
- 允许少、允许迟、允许 abstain；不允许填充、夸大或无证据确定性。

## 成功指标

生产候选必须同时满足：

- 50–100 条历史资讯回放完成。
- AI Daily 与 IELTS 连续 7 个真实 shadow 日；Weekly 完成历史回放和至少 1 个真实周。
- 核心证据 URL 可达且内容匹配率 100%。
- accepted critical claim 的实质错误为 0。
- 覆盖、删除、移动、重命名和范围外 Vault 读取为 0。
- 认证、额度、断网、429/5xx、目标冲突和进程强杀都安全失败。
- 用户连续一周认为至少 80% 的 Top 值得占用注意力。
- 至少 90% 个性化结论能追溯到显式 UserContext 字段。

这些是个人生产验收线，不是对未来永远零错误的承诺。

## 非目标

- 多用户、多租户、企业合规或对抗本地管理员。
- 公网服务、Local UI、REST 写入、数据库或消息队列。
- 自动沉淀到 `10-Notes`、`20-Sources` 或修改既有笔记。
- 追求每天固定条数、全网覆盖或“所有内容都经两个模型”。
- 物理掉电后的事务级 durability、不可抵赖审计或异地灾备。
- 自动购买 API、切换 DeepSeek 或用低质量 fallback 保持形式完整。

## 投入优先级

- 50%：来源、证据与内容评估。
- 25%：端到端稳定性与状态体验。
- 15%：数据边界与不覆盖。
- 10%：部署和与真实威胁相称的安全强化。
